# 02. 環境設計書

## 1. 目的

本書は、web-infra-portfolio における dev環境 / prod環境 の設計方針を定義します。

本ポートフォリオでは、単一環境ではなく、検証用の dev と本番想定の prod を分離することで、実務に近い運用設計を表現します。

## 2. 環境一覧

| 環境 | 目的 |
|---|---|
| dev | 検証、障害演習、パッチ検証 |
| prod | 本番想定、安定稼働、変更管理 |

## 3. dev環境

dev環境は、検証を目的とした環境です。

### 主な用途

- Apache設定変更の検証
- WebLogic設定変更の検証
- Oracle接続確認
- OSパッチ検証
- 障害再現
- ロールバック検証

### 設計方針

| 項目 | 方針 |
|---|---|
| 可用性 | 最小構成 |
| コスト | 低コスト優先 |
| セキュリティ | 最低限の制限 |
| 変更頻度 | 高い |
| 証跡 | 必要に応じて取得 |

## 4. prod環境

prod環境は、本番想定の環境です。

### 主な用途

- 本番想定構成の設計
- 変更管理手順の作成
- 監視設計
- ロールバック設計
- 障害対応フロー作成

### 設計方針

| 項目 | 方針 |
|---|---|
| 可用性 | 冗長化を考慮 |
| コスト | 本番想定優先 |
| セキュリティ | 厳格 |
| 変更頻度 | 低い |
| 証跡 | 必須 |

## 5. 想定AWS構成

### dev

```text
VPC
├ Public Subnet
│  └ EC2 Apache
└ Private Subnet
   └ EC2 WebLogic/Oracle検証
```

### prod

```text
VPC
├ Public Subnet
│  └ Apache
├ Private Subnet
│  └ WebLogic
└ DB Subnet
   └ Oracle想定
```

## 6. Terraform管理

Terraformでは以下のように環境を分離します。

```text
terraform/
├ modules/
└ envs/
   ├ dev/
   └ prod/
```

### dev

- 小規模構成
- 検証優先
- 手動apply想定

### prod

- 本番想定構成
- 変更管理あり
- apply前レビュー必須

## 7. 環境差分

| 項目 | dev | prod |
|---|---|---|
| 用途 | 検証 | 本番想定 |
| EC2台数 | 少数 | 役割分離 |
| Subnet | 最小 | Public/Private/DB |
| 監視 | 最小 | 必須 |
| 変更管理 | 簡易 | 必須 |
| ロールバック | 演習 | 必須 |

## 8. セキュリティ方針

- SSHは限定IPのみ許可
- 秘密鍵はGit管理しない
- セキュリティグループは最小権限
- prodは公開範囲を最小化する
- DBはPublic Subnetに配置しない

## 9. ロールバック方針

変更前には必ず以下を取得します。

- 設定ファイルバックアップ
- サービス状態
- バージョン情報
- ログ
- Terraform plan結果

変更失敗時は、事前取得したバックアップを用いて切り戻します。

## 10. 証跡方針

作業時は以下を証跡として残します。

- 作業前状態
- 実施コマンド
- 作業後状態
- ログ
- 確認結果
- ロールバック判断
